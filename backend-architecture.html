Home / Technology / Backend & API

Node.js, MySQL, and a hybrid rule-plus-AI brain.

Inside the AgroScan Backend: the frameworks, the database layer, and every API endpoint group that powers the ecosystem.

The AgroScan Backend forms the intelligence and data management core of the ecosystem. Built using Node.js (Express) and MySQL, it powers user authentication, device synchronisation, soil and weather data storage, AI-driven recommendations, and chat-based support — combining local rule-based logic with external AI services for both precision and adaptability.

Core frameworks & libraries

  • Express.js — web framework handling API routing.
  • dotenv — manages environment configuration.
  • mysql2/promise — async/await MySQL connections.
  • bcrypt — secure password hashing (developer-side).
  • multer — handles file uploads (e.g. profile images).
  • cors & body-parser — request handling and cross-origin policy.

System components

Database Layer: a MySQL connection pool holds relational data across users, lands, orders, ai_chats, controls and dev_users.

Local Logic Layer: ruleEngine.js interprets soil pH, moisture and temperature for instant offline recommendations, backed by PreassignedCommands.js for fast default chatbot responses.

AI Integration Layer: Perplexity handlers combine rule-based results with AI recommendations for reliability.

API ENDPOINT GROUPS

Eight groups of endpoints, one server.

GroupWhat it covers
Health & System/, /test, /api/server/stats — status, AI provider, CPU/memory metrics.
User Management/api/signup, /api/login, profile CRUD, password change, profile image.
Land Management/api/users/:userId/lands — CRUD for farmland entries with ownership checks.
Orders Module/api/users/:userId/orders — AgroShop transactions with rollback on failure.
Recommendations/recommend — accepts soil parameters, calls ruleEngine() plus AI for hybrid results.
AI Chat System/chat, /api/chat/history/:userId, /api/chat/clear/:userId.
Controls & Config/api/controls — feature toggles for enabling/disabling AI features or test modes.
Developer & Admin Desk/api/dev-login, /api/sql-run (restricted), /api/devusers/:id, /api/dev/tables.

Design logic

  • Transaction safety — rollbacks on delete or multi-row insert.
  • Security — developer access gated by tokens (bcrypt rollout planned).
  • File management — profile images stored as binary via in-memory multer upload.
  • Resilience — rule engine (offline) + AI layer (cloud) working together.

Planned enhancements

  • Migrate to bcrypt for all user password storage.
  • Add JWT-based authentication for mobile and web APIs.
  • Enable Redis caching for frequent AI calls.
  • Implement role-based access control (RBAC).
  • Add webhooks and APIs for third-party data partners.
